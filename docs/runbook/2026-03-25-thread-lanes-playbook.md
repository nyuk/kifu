# Thread Lanes Playbook

## 목적

여러 환경과 여러 작업 축이 섞이면서 문맥이 자주 꼬였다.

예:
- 윈도우 Codex에서 Kifu 메인 제품 작업
- 윈도우 Codex에서 Kifu 디자인 작업
- 윈도우 Codex에서 Kifu 마케팅 작업
- 윈도우에서 프리미엄 알림봇 운영 작업
- 맥에서 프리미엄 백테스트 연구
- 맥에서 Kifu ACP / OpenClaw 관련 작업
- 맥에서 아이디어 정리

이 문서는 새 스레드를 열 때 먼저 **어떤 레인(lane)** 인지 분명히 선언해서, 서로 다른 문맥이 섞이지 않게 만드는 공용 플레이북이다.

이 문서는 Codex와 Claude 둘 다 사용할 수 있게 작성한다.

## 기본 원칙

새 스레드를 시작할 때는 아래 3가지를 먼저 말한다.

1. 현재 환경
2. 현재 레인
3. 이번 스레드의 목표

이 3가지만 먼저 분명하면, 포트/경로/문서/작업 범위가 덜 섞인다.

## 환경 분류

현재 자주 쓰는 환경은 아래처럼 본다.

- `윈도우 Codex`
- `맥 Codex`
- `윈도우 Claude`
- `배포 서버`

중요한 점:
- 같은 Kifu 작업이라도 환경에 따라
  - repo 경로
  - shell 문법
  - frontend/backend 포트
  - `.env` 위치
  - 실행 방법
  - 현재 떠 있는 프로세스
  가 다를 수 있다.

그래서 스레드 시작 시 환경을 먼저 말하는 것이 중요하다.

## 레인 분류

현재 작업 레인은 아래처럼 구분한다.

### 1. Windows Kifu Main

사용 시점:
- 거래복기 서비스 메인 기능 작업
- 리뷰, 차트, 버블, 성장, 프리셋, 알림, 설정, 온보딩

이 레인에서 기대하는 것:
- 실제 제품 기능 구현
- 백엔드/프런트 연동
- 핵심 사용자 흐름 개선

섞지 말아야 할 것:
- 마케팅 콘텐츠 운영
- 프리미엄 알림봇 운영
- 프리미엄 백테스트 연구

### 2. Windows Kifu Design

사용 시점:
- 홈 / 리뷰 / 차트 / 버블 / 셸 구조 디자인
- 글자 크기, 버튼 표현, 간격, 정보 위계, 화면 정리

이 레인에서 기대하는 것:
- 거래복기 서비스처럼 느껴지게 만드는 UX 정리
- 시각적 통일성과 정보 구조 개선

섞지 말아야 할 것:
- 운영 툴/관리자 화면 작업
- 마케팅 생성 흐름
- 프리미엄 봇/백테스트 맥락

### 3. Windows Kifu Marketing

사용 시점:
- Marketing OS
- X / 블로그 초안 생성
- 승인 / 발행 / 마케팅 워크플로우

이 레인에서 기대하는 것:
- 콘텐츠 운영 UX
- 마케팅 초안 품질 개선
- Marketing OS와 제품 기능 연결

섞지 말아야 할 것:
- 차트 / 리뷰 메인 UX
- 프리미엄 봇 운영
- 백테스트 연구

### 4. Windows Premium Alert Bot

사용 시점:
- 프리미엄 알림봇 런처
- 중복 실행
- watchdog
- health
- 실제로 봇이 돌고 있는지 확인

이 레인에서 기대하는 것:
- 운영 점검
- 런타임 이슈 해결
- 배치/런처/상태 파일 확인

섞지 말아야 할 것:
- Kifu 프런트 디자인
- Marketing OS
- 백테스트 연구

### 5. Mac Premium Backtest

사용 시점:
- 프리미엄 전략 백테스트
- 실험 비교
- challenger / champion 판단
- sweep 결과 해석

이 레인에서 기대하는 것:
- 연구 결과 해석
- 대시보드 반영 전 판단
- 실험 결과 정리

섞지 말아야 할 것:
- Kifu 메인 UI 작업
- 프리미엄 봇 런타임 운영

### 6. Mac Kifu ACP

사용 시점:
- ACP
- OpenClaw spike
- seller flow
- onchain quick fact check

이 레인에서 기대하는 것:
- ACP / OpenClaw 판단
- 전달 경로 정리
- seller 자산/문서/체크리스트 관리

섞지 말아야 할 것:
- 일반 Kifu 기능 작업
- 마케팅
- 프리미엄 백테스트

### 7. Mac Ideas

사용 시점:
- 아이디어만 정리하고 싶을 때
- 아직 구현/운영/디자인 어느 쪽으로 갈지 안 정했을 때

이 레인에서 기대하는 것:
- 아이디어 압축
- 우선순위 정리
- 다음에 어느 레인으로 보낼지 판단

섞지 말아야 할 것:
- 바로 코드 구현
- 운영 명령 실행

## 새 스레드 시작 템플릿

아래 형식을 그대로 복붙해서 시작하면 된다.

```text
현재 환경: [윈도우 Codex / 맥 Codex / 윈도우 Claude / 배포 서버]
현재 레인: [Windows Kifu Main / Windows Kifu Design / Windows Kifu Marketing / Windows Premium Alert Bot / Mac Premium Backtest / Mac Kifu ACP / Mac Ideas]
이번 목표: [이번 스레드에서 하고 싶은 일]

이 스레드에서는 이 레인 범위 안에서만 생각하고,
다른 레인 맥락은 섞지 말아줘.
필요하면 먼저 읽어야 할 파일/문서부터 짚어줘.
```

## 바로 쓸 수 있는 예시

### 예시 1. 거래복기 메인 기능

```text
현재 환경: 윈도우 Codex
현재 레인: Windows Kifu Main
이번 목표: 리뷰 완료 후 홈으로 돌아오는 흐름과 차트 연동을 정리하고 싶어.

이 스레드에서는 거래복기 서비스 메인 제품 작업만 보고,
마케팅이나 프리미엄 봇 문맥은 섞지 말아줘.
먼저 읽어야 할 파일부터 확인해줘.
```

### 예시 2. 거래복기 서비스 디자인

```text
현재 환경: 윈도우 Codex
현재 레인: Windows Kifu Design
이번 목표: 홈, 리뷰, 차트를 거래복기 서비스처럼 더 정돈된 디자인으로 만들고 싶어.

이 스레드에서는 디자인과 정보 구조 중심으로 보고,
불필요한 백엔드 변경은 최소화해줘.
```

### 예시 3. 마케팅

```text
현재 환경: 윈도우 Codex
현재 레인: Windows Kifu Marketing
이번 목표: X 초안 2개와 블로그 초안 1개를 만들고 Marketing OS 흐름도 같이 점검하고 싶어.

이 스레드에서는 마케팅 운영 흐름만 보고,
차트나 리뷰 메인 UX 문맥은 섞지 말아줘.
```

### 예시 4. 프리미엄 알림봇 운영

```text
현재 환경: 윈도우 Codex
현재 레인: Windows Premium Alert Bot
이번 목표: 지금 알림봇이 실제로 돌고 있는지와 중복 실행 여부를 확인하고 싶어.

이 스레드에서는 봇 운영/런타임만 보고,
Kifu UI 문맥은 섞지 말아줘.
```

### 예시 5. 프리미엄 백테스트 연구

```text
현재 환경: 맥 Codex
현재 레인: Mac Premium Backtest
이번 목표: 최근 전략 후보 두 개를 비교해서 어떤 후보를 유지할지 판단하고 싶어.

이 스레드에서는 백테스트 연구만 보고,
Kifu 기능 구현이나 운영 이슈는 섞지 말아줘.
```

### 예시 6. ACP / OpenClaw

```text
현재 환경: 맥 Codex
현재 레인: Mac Kifu ACP
이번 목표: ACP 유지/병행/전환 중 어떤 쪽이 맞는지 정리하고 싶어.

이 스레드에서는 ACP와 OpenClaw 판단만 보고,
일반 Kifu 기능 작업은 섞지 말아줘.
```

### 예시 7. 아이디어 정리

```text
현재 환경: 맥 Codex
현재 레인: Mac Ideas
이번 목표: 생각 중인 기능 아이디어를 정리하고 어느 레인으로 보낼지 분류하고 싶어.

이 스레드에서는 구현보다 아이디어 정리만 우선해줘.
```

## Codex / Claude 공통 사용법

이 문서는 특정 에이전트 전용이 아니다.

Codex든 Claude든 새 스레드에서 아래 한 줄만 먼저 분명히 말하면 된다.

```text
현재 환경: ...
현재 레인: ...
이번 목표: ...
```

그 다음부터는:
- 먼저 읽을 파일
- 피해야 할 문맥
- 바로 들어갈 구현/정리 범위
를 정리해 달라고 하면 된다.

## 추천 운영 방식

### Codex

- 레인별로 스레드를 나눠서 유지
- 같은 레인의 작업은 한 스레드에 누적
- 다른 레인 작업은 새 스레드로 분리

### Claude

- 꼭 같은 스레드 구조를 만들 필요는 없음
- 대신 새 작업을 시작할 때마다
  - 현재 환경
  - 현재 레인
  - 이번 목표
  를 먼저 붙이면 충분함

## 기억할 것

가장 중요한 것은 스레드마다 아래 3가지를 먼저 분명히 하는 것이다.

1. 지금 어디서 작업하는지
2. 지금 어떤 레인인지
3. 이번 스레드 목표가 무엇인지

이 3개만 먼저 분명하면, 포트/경로/문서/명령/문맥이 섞이는 일이 크게 줄어든다.
