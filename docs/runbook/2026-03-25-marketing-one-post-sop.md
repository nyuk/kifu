# Marketing OS One-Post SOP

기준 날짜: 2026-03-25  
기준 브랜치: `main`  
대상 레인: `Windows Kifu Marketing`

## 목적

이 문서는 현재 `Marketing OS` 구현 기준으로
글 1편을 실제로 만드는 운영 흐름을 빠르게 따라가기 위한 SOP다.

중요한 원칙:

- 이 문서는 현재 repo 기준으로 실제 되는 흐름만 다룬다.
- 차트 메인 UX, 리뷰 메인 UX, Growth OS 문맥은 섞지 않는다.
- 자동 발행이 아니라 `수동 발행 + 앱 내 기록` 기준으로 본다.

## 현재 범위

현재 `/marketing`에서 가능한 범위는 아래다.

1. 아이디어 저장
2. 채널별 초안 생성
3. 초안 수정
4. 초안 승인 / 보류 / 폐기
5. 발행 URL 기록
6. 네이버 블로그 채널 설정 저장

현재 구현 바깥으로 보는 항목:

- 외부 채널 자동 발행
- 예약 발행 자동화
- 성과 수집 자동화
- 운영 아카이브 전용 화면

## 시작 전 체크

1. 관리자 세션으로 로그인되어 있어야 한다.
2. `/marketing` 진입이 되는지 확인한다.
3. 이번 글이 어떤 채널용인지 먼저 정한다.
   - `X`
   - `네이버 블로그`
   - `유튜브`
4. 이번 글의 성격을 먼저 정한다.
   - `직접 광고`
   - `은근한 연결`
   - `비광고 글`

## 1. 아이디어 인박스에 저장

캡처 탭에서 아래를 채운다.

- 제목
- 원본 메모
- 콘텐츠 각도
- 참고 링크
- 콘텐츠 성격
- 근거 출처
- 표현 형식
- 핵심 메시지
- 채널

이미지나 차트를 같이 쓰고 싶으면:

- 이미지 붙여넣기 또는 업로드
- 이미지별 메모 1~2줄 입력

권장 입력 기준:

- `원본 메모`에는 무슨 일이 있었는지와 왜 중요한지까지 적는다.
- `뉴스` 또는 `인용`이면 `참고 링크`를 넣는다.
- `스크린샷` 또는 `생성 이미지`면 실제 이미지를 붙인다.
- `은근한 연결` 이상이면 `기록 / 복기 / 메모 / 기준 / 진입 / 청산` 중 하나가 메모에 들어가는 편이 좋다.

저장 후 기대 상태:

- 아이디어가 목록에 들어간다.
- 방금 저장한 아이디어가 바로 선택된다.

## 2. 초안 생성 가능 상태 확인

아이디어를 클릭하면 상세와 함께 초안 생성 체크가 보인다.

여기서 본다:

- `blocking`
  초안 생성 전에 반드시 보강해야 하는 항목
- `warning`
  생성은 가능하지만 결과 품질에 영향을 줄 수 있는 항목

실무 기준:

- `blocking`이 있으면 먼저 메모를 보강한다.
- `warning`만 있으면 일단 생성해도 된다.

## 3. 채널별 초안 생성

아이디어 카드에서 채널 버튼을 눌러 초안을 생성한다.

권장 순서:

1. 오늘 가장 먼저 발행할 채널 초안 생성
2. 결과가 괜찮으면 다른 채널로 확장

현재 동작:

- 생성 직후 아이디어 상태가 `draft_ready`로 바뀐다.
- 생성된 초안이 리뷰 탭에서 바로 선택된다.

운영 메모:

- 초안은 `완성본`이 아니라 `검토용 초안`으로 본다.
- 특히 `X`는 짧기 때문에 첫 생성본을 그대로 발행하기보다 한 번 다듬는 걸 기본으로 본다.

## 4. 리뷰 탭에서 초안 정리

리뷰 탭에서 아래를 확인한다.

- 제목
- 톤
- 상태
- 본문
- 리스크 플래그

기본 작업 순서:

1. 첫 문단이 실제 장면이나 문제를 잡고 있는지 본다.
2. 쓸데없이 일반론으로 흐르지 않는지 본다.
3. 제품 연결이 과한지, 약한지 조정한다.
4. 리스크 플래그에 걸릴 만한 과장 표현이 없는지 본다.

`X` 운영 기준:

- 2문단 안에서 끝내는 편이 안정적이다.
- 예측, 전략, 매수/매도 신호처럼 읽히는 문장은 뺀다.
- 같은 날 이미 홍보성 글을 올렸다면 `비광고` 또는 `은근한 연결` 쪽으로 조정한다.

## 5. 상태 결정

초안 편집 후 아래 중 하나로 둔다.

- `승인 대기`
  아직 손볼 것이 남아 있는 초안
- `승인 완료`
  외부 채널에 실제로 올려도 되는 상태
- `보류`
  아이디어는 좋지만 오늘은 안 쓰는 초안
- `폐기`
  방향이 맞지 않아서 버리는 초안

실무 권장:

- 같은 날 바로 쓸 글이면 `승인 완료`
- 다음에 다시 볼 가능성이 있으면 `보류`
- 다시 쓸 가능성이 거의 없으면 `폐기`

## 6. 외부 채널에 수동 발행

현재는 앱 안에서 자동 발행되지 않는다.

즉 실제 발행은:

1. 초안 편집기에서 본문 복사
2. 외부 채널로 이동
3. 최종 다듬기
4. 수동 게시

발행 직전 체크:

- 오타
- 링크
- 같은 날 톤 중복 여부
- 과장 표현
- 투자 조언처럼 읽히는 표현

## 7. 발행 URL 기록

게시가 끝나면 다시 `/marketing`으로 돌아와서:

1. 해당 초안을 선택
2. 발행 URL 입력
3. 발행 기록 저장

현재 기준으로는 `승인 완료` 초안만 발행 URL 기록이 가능하다.

이 단계까지 하면 글 1편의 운영 사이클이 끝난다.

## 8. 완료 기준

한 편이 완료됐다고 볼 기준:

- 아이디어가 인박스에 남아 있다
- 채널별 초안이 생성돼 있다
- 최종 초안 상태가 정리돼 있다
- 외부 채널에 실제 게시가 끝났다
- 발행 URL이 저장돼 있다

## 자주 막히는 지점

### 1. 초안 생성 전 막힘

원인:

- 메모가 너무 짧음
- 뉴스인데 링크 없음
- 이미지 근거인데 이미지 없음
- 스크린샷 근거인데 무엇을 보여주는지 설명이 없음

대응:

- `원본 메모`를 먼저 보강
- 이미지 메모를 한 줄 추가
- 필요하면 `proof points`를 채움

### 2. 초안이 너무 평범함

원인:

- 입력 메모가 사건 설명만 있고 문제의식이 약함
- 실제 장면보다 일반론이 많음
- 채널 성격보다 제품 설명이 먼저 나옴

대응:

- `그날 왜 중요했는지`
- `트레이더가 무엇을 놓치기 쉬운지`
- `나중에 무엇을 다시 확인하고 싶은지`

이 3개를 메모에 더 적는다.

### 3. 발행 기록이 비어 있음

원인:

- 실제 게시 후 앱으로 다시 안 돌아옴

대응:

- 수동 발행 직후 바로 URL 저장까지 한 세트로 묶는다.

## 다음 점검 우선순위

이 SOP를 실제로 1회 따라 해본 뒤에는 아래 순서로 점검하는 게 좋다.

1. 어떤 단계에서 가장 오래 멈췄는지 기록
2. 초안 생성 전 보강 메시지가 충분히 명확했는지 확인
3. 발행 후 URL 기록이 자연스러운지 확인
4. 같은 아이디어를 다른 채널로 확장하는 흐름이 매끄러운지 확인
